# 1. C程序与Verilog描述电路联系
***RTL仿真的本质是通过软件程序来模拟硬件的行为***  
从流水灯电路的C仿真程序来看，C程序无非在做三件事情：  
1. 电路状态初始化
2. Eval激励对电路状态求值，并在update中统一更新电路状态(非阻塞语义，硬件并行执行的前提)
3. 打印记录电路状态。
```c
int main() {
  reset(&circuit);
  while (1) {
    cycle(&circuit);
    display(&circuit);
  }
  return 0;
}
```
将RTL代码描述的硬件电路翻译为模拟硬件电路行为的软件程序，这种翻译工具就称之仿真器.  
典型的开源仿真器`verilator`，就是将SystemVerilog描述的电路翻译为执行速度极快的C++代码  
verilator调用命令格式为:`$ verilator <options> <verilog-file> <stimu-cpp-file>`  
其中，<verilog_file> 是需要仿真的 Verilog 文件，<cpp_file> 是手动编写的 C++ 激励文件。<options> 是一些编译选项，这里列出一些常用的编译选项：  
- --cc：指定将 Verilog 代码转化为 C++ 代码；  
- --exe：指定生成目标为可执行文件；
- --build：直接编译生成目标文件；
- --trace：导出波形文件时需要添加此选项；
- --top-module <top-module>：指定 Verilog 顶层模块；
- --Mdir <build-dir>：指定生成文件的目录；
- -CFLAGS <c-flags>：指定一个 GCC 的编译选项；
- -I <include-path>：可以指定一个包含路径

# 4. 事件模型分析verilog代码行为
```Verilog
always @(posedge clk) begin
  b  = a;  // b=1  b=5
  c <= b;  // c=3  c=1
```

# 阅读Verilog手册了解综合与仿真不一致的行为
常见的综合仿真不一致行为有：
- 电路模块引入延迟符#和不可综合语义initial
- 时序电路中用阻塞赋值，组合电路中用非阻塞赋值
- case情况不列全，default逻辑缺失综合出latch
- casez/casex错误地把高组态/多驱动信号给屏蔽

# 7. 找出错误描述
1. 使用#0可以将赋值操作强制延迟到当前仿真时刻的末尾.
   >正确，但不建议这么做，在不清楚需求的情况下强行改变求值顺序容易引发问题；
2. 在同一个begin-end语句块中对同一个变量进行多次非阻塞赋值, 结果是未定义的.
   >不正确，同一begin-end块内属于同一进程，对同一变量进行多次非阻塞赋值，R1区域的求值队列顺序执行，求值固定为最后一次结果。同样R3区域更新队列也是顺序执行，更新结果也是最后一次赋值。
3. 用always块描述组合逻辑元件时, 不能使用非阻塞赋值.
   >不正确，组合逻辑中可以使用非阻塞赋值，但其结果会综合出一个锁存器电路，虽然可以这么做但要尽量避免。会引入一个无限小但是存在的cycle_delta,仿真层面读到的是新值，但物理层面读到的是旧值，导致仿真与综合不一致
4. 不能在多个always块中对同一个变量进行赋值.
   >正确，同一变量无论是阻塞赋值还是非阻塞赋值，其结果都不定跟always块的执行顺序有关，属于未定义行为。
5. 不建议使用$display系统任务, 因为有时候它无法正确输出变量的值.
   >不完全正确，取决于需求，如果要打印R1区域的变量值就只能用$display，如果是其他区域就不行。
6. $display无法输出非阻塞赋值语句的结果
   >正确，$display是立即打印R1队列的状态值，而非阻塞语句结果还在R3队列

# 电路功耗评估
- **Internal Power内部功耗**: CMOS管开关某一瞬间短路产生峰值电流作用在等效电阻上的功耗  
  $$P_{internal} = I_{peak}^2 \cdot R_{eq}$$

- **Switch Power 翻转功耗**：CMOS管电平从0-1翻转过渡过程中为等效电容充放电消耗的功耗，α表示翻转概率  
  $$P_{switch} = \alpha \cdot C_{load} \cdot V_{dd}^2 \cdot f$$

- **Leakage Power静态功耗**: 晶体管截止状态下理想电流为0，实际情况会有微小的漏极电流通过，即便晶体管不翻转也会产生的静态功耗，其中漏极电流容易受温度的影响。  
  $$P_{leakage} = I_{leakage} \cdot V_{dd}$$

# 理解驱动能力
可以将晶体管驱动能力比喻为同时往下游闸门放电流的闸门数，越多的闸门一可以往下游放更多的电流，下游晶体管充满电的速度就越快动态特性就越好，与之伴随的代价就是放闸门的一瞬下游电流激增，虽然尖峰时长短了但电流激增引发的总体内部功耗更大了，而且电流激增导致下游经过导线的功耗增加，而且闸门平时关着的时漏掉的电流也越多静态功耗增加。

# 了解IO单元尺寸
`ICSIOA_N55_3P3`：表示 IO 单元库，`N55` 工艺，`3.3V` 电源。  
后缀如 `ss_1p08_2p97_m40c、ff_1p32_3p63_125c` 等，表示不同的工艺角（PVT）：  
`ss：slow-slow`（慢工艺，低电压，低温），最坏延迟。  
`ff：fast-fast`（快工艺，高电压，高温），最快延迟。  
`tt：typical-typical`（典型工艺，典型电压，典型温度）。  
`1p08、1p32、1p2`：表示核心电压（如1.08V、1.32V、1.2V）。  
`2p97、3p63、3p3`：表示 IO 电压（如2.97V、3.63V、3.3V）。  
`m40c、125c、0c、25c`：表示温度（如-40℃、125℃、0℃、25℃）

# 9. PDK标准单元电气特性
## 9.1 标准单元属性
- lib文件给出了各种标准单元的面积大小、各种逻辑输入下的动态功耗和漏电功耗、延迟信息和翻转动态参数
- lef文件则给出了单元的几何尺寸、位置信息、各个层级以及对应的线宽线距信息
- .v文件则给出了行为仿真的样式，仿真器会将按照.v文件提供的延时信息和逻辑运算来进行仿真模拟,.v文件中的延时参数又是由后仿真后通过SDF注入的。
- .cdl文件给出了晶体管层的工艺参数，如晶体管类型、拓扑结构、沟道信息
## 9.2 标准单元分类
- 基本门单元：基本的与或非异或逻辑门的实现
- 时序单元：各种触发器锁存器等时序单元的实现，以及同步异步使能置位等变种
- IO单元，由于IO负责与芯片外部进行通信交互，涉及到信号的出入对稳定性、抗干扰、驱动性能要求极高需要用到大量稳定电路结构的元件，因此IO单元的面积占用也比一般标准单元要大。
- 物理单元：无实际逻辑含义但有物理意义的模块，例如空白填充，去耦单元(大量晶体管同时翻转时，为保证vss供电稳定性的电量蓄池)，天线修复单元
- 宏单元：预定义好的常见SRAM\DDR\PHY之类的电路单元。
- 复杂功能单元：常见的加法器、选择器、译码器基本单元。
- 调试单元：为更好地定位硬件电路bug，插入一些调试扫描单元，具体为为触发器增加扫描使能端和扫描输入端辅助后续DFT实测调试。
- 时钟树单元：时钟是个极其重要的全局信号，它同样对稳定性、抗干扰、驱动能力有极高要求， 和一般的标准单元相比, 标准单元库的设计者需要对时钟专用单元进行专门综合, 使其具备低抖动, 低延迟, 高驱动能力等特性.本质就是为了保证时钟信号尽可能地同时传递到时序单元，在中间路径短的地方插入buffer，使其成为一颗平衡树。
## 9.3 工艺角PVT
晶体管的延迟是由三个主要变量影响，既工艺Process、电压Voltage、温度Temperature.由于制造工艺存在不可避免的误差例如光刻胶浓度、晶圆厚薄、晶体管掺杂浓度不均，不同的电源环境，以及不同的工况温度。后端工程师为了囊括所有的制造误差和工况，在布线阶段就得把所有的PVT组合考虑在内然后进行SDF提取，保证量产的芯片在各种工况下造成的误差在各种极端工况下都能收敛符合spec设计预期，不同的PVT组合会给出不同的lib文件。此外同一芯片内部也会因晶体管密度、功耗发热、制造工艺误差引入的一些延迟，后端一般会留有悲观因子和设计裕量cover住这一误差。

## 9.4 阈值电压
晶体管的由于制造工艺的本质区别，不同的阈值电压对应不同的延迟和静态功耗，他俩是一对不可调和的矛盾参数，直观表现就是延迟(芯片速度)和功耗(发热)的不可调和。越高的阈值电压有着越大的延迟，好处是漏极电流小静态功耗低，反之亦然。因此PDK工艺库还会提供类似于PVT角的，还会给阈值电压角HVT,后端工程师可以根据模块所在区域实际的PPA做出最合适的选择。
# 10 物理布线
# 10.1 布线步骤
后端布线的布置步骤为：初步评估利用率和芯片面积参数，根据spec规划，先确定引脚数和布局方案，为IO单元布局，再为IO供电单元布局，再摆放全局电源，再摆放宏单元，再将时钟单元布局，再为标准单元布局，布局完毕后开始布线。总体准则是由外到内，先大后小，取舍得当，目标是低延迟低功耗少面积，合理规划出最终的布线版图。
# 10.2 签核分析
后端时序符合并通过了各种一致性检查后，仅是保证了物理上对齐了上游的设计正确性，但还要考虑对齐下游制造的正确性，因此还最后一道步骤：签核sign off，这个步骤会从已经布线好的版图中提取各种延时信息进行STA和物理验证，并进行制造规则和电气检查，确保最后的版图是符合晶圆厂生产标准的。
# 10.3 产品良率
最后的产品良率会受到晶圆厂加工误差，车间无尘度等影响，另外还会受到后端工程师布局布线密度，几何图形过于复杂，制造设备无法完美还原版图，还有就是芯片面积，过大的芯片面积容易引入更多的杂尘导致良率降低。过于激进和过于保守的设计和布线都会引起良率下降导致单颗芯片成本提高,因此半导体工程师更像是走钢丝，极其看重岗位经验。

# 11. Verilog理解测试
- 在硬件描述语言中, "执行"的精确含义是什么?
   >对于组合逻辑，执行就是仿真模型完成清空R2的事件队列，对于时序逻辑，执行就是R3事件队列的清空。
- 是谁在执行Verilog的语句? 是电路，综合器，还是其它的?
  >是软件在执行verlog程序，这类软件称之为仿真器，它通常把verlog中的高级语言转换为许多个并发执行的线程，用软件来达到模拟硬件并发执行的效果。综合器(可理解为硬件编译器，本质还是个软件)则会把verilog描述的代码块例化并转换为PDK库中标准单元为基本单位的网表文件。
- if的条件满足, 就不执行else后的语句, 这里的"不执行"又是什么意思? 和描述电路有什么联系?
  >对于仿真器来说，不执行就是仿真器不会创建else块内的事件队列，对综合器来说不执行就意味着else块对应的那条数据通路永远不会被激活。
- 有"并发执行", 又有"顺序执行", 还有"任何一个变量发生变化就立即执行", 以及"在任何情况下都执行", 它们都是如何在设计出来的电路中体现的?
  >并发执行体现在多个always块内的变量非阻塞赋值，如时序单元的赋值更新；顺序执行则体现在R2区域事件队列的先来后到，如组合逻辑门的前后级联，变化则立刻执行体现在always块的敏感变量列表，如DFF的触发边沿、复位方式、置位值定义。任何情况都执行体现在物理定律的连续性，例如assign a=b意味着ab永远共享着同一电平状态。

- 串行加法器:
  >全加器的进位Cout串联下一个全加器的Cin，优点是线路简单直观，对面积要求相对较低。缺点则是因为最高位的进位输出依赖于上一级的进位输入，电路关键路径太长不适合高速场景。

  **全加器公式：**
  $$S_i = A_i \oplus B_i \oplus C_i$$
  $$C_{i+1} = A_i \cdot B_i + (A_i \oplus B_i) \cdot C_i$$

  其中 $S_i$ 为第 $i$ 位的和，$C_i$ 为第 $i$ 位的进位输入，$C_{i+1}$ 为进位输出。

- 超前进位加法器
  >进位信息可以通过多输入逻辑门提前计算，优点是关键路径被大大缩短，适合高速加法场景。然而代价就是多输入逻辑门的面积占用较大，且当加法器位长较大时，大扇入逻辑门带来的延时效应也不可忽视。

  **定义生成信号(Generate)和传播信号(Propagate)：**
  $$G_i = A_i \cdot B_i$$
  $$P_i = A_i \oplus B_i$$

  **进位递推公式：**
  $$C_{i+1} = G_i + P_i \cdot C_i$$

  **展开后的超前进位公式：**
  $$C_1 = G_0 + P_0 \cdot C_0$$
  $$C_2 = G_1 + P_1 \cdot G_0 + P_1 \cdot P_0 \cdot C_0$$
  $$C_3 = G_2 + P_2 \cdot G_1 + P_2 \cdot P_1 \cdot G_0 + P_2 \cdot P_1 \cdot P_0 \cdot C_0$$
  $$C_4 = G_3 + P_3 \cdot G_2 + P_3 \cdot P_2 \cdot G_1 + P_3 \cdot P_2 \cdot P_1 \cdot G_0 + P_3 \cdot P_2 \cdot P_1 \cdot P_0 \cdot C_0$$

  **通用公式：**
  $$C_n = G_{n-1} + \sum_{i=0}^{n-2}\left( G_i \cdot \prod_{j=i+1}^{n-1} P_j \right) + C_0 \cdot \prod_{i=0}^{n-1} P_i$$
